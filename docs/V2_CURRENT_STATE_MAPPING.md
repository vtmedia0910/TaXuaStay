## What is actually implemented today

- site settings, Supabase Auth, `admin`/`staff`, RLS, and Admin shell;
- Destination-owned properties, room types, stable physical Room IDs, amenities, and exclusive property/room-type/physical-room media;
- verification lifecycle, Cloud View, Road Verified, exact-target evidence, 360, Room Quality dimensions, and ordered public strengths/caveats;
- integer-VND room sell pricing and price confidence;
- pooled room-type inventory, freshness-aware availability, and Admin bulk updates;
- room-first search, public property/room routes, SEO landings, sitemap, robots, and temporary-host `noindex` safety.
- structured Homepage/Stay/Footer editorial content, website media, protected draft preview and atomic page publishing, with code fallbacks.
- private Supplier identities, contacts, Property roles/history, Partner lifecycle/tier, and opaque external-system references with no anonymous access; Phase 3H adds one canonical archive RPC, direct-archive protection, non-reopening reactivation, and stable primary-contact edits.
- a small Trip-owned motorbike catalog projection, manual/reference provider adapter, `/motorbike`, and Admin controls linked to a real motorbike Supplier plus `taxua_biker` external reference; no production rows are seeded.
- a real Package domain with generic ordered components, explicit current Package pricing, private aggregate economics, availability/confirmation aggregation, `/packages`, and `/admin/packages`; no production rows are seeded.
- deterministic `/trip-finder` decision support across real Room, Package, Motorbike and individual-composition candidates, with hard constraints, explicit unknowns and no commercial-ranking inputs.
- one private traveler Booking with many immutable item snapshots, separate Supplier Confirmation, opaque-token safe status, Admin operations and append-only audit events.
- versioned quote/requote history, Admin-controlled deposit/cancellation policy, deterministic `phase9-checkout-readiness-v1`, amount due/remaining balance and quote-bound provider-unconfigured checkout drafts.
- a secure mobile-first My Trip projection at `/booking/[bookingCode]` with customer status, immutable component snapshots, quote/deposit/readiness, safe timeline and configured support actions; no customer account or new state machine.
- a private mobile-first Operations home and Booking inbox with deterministic attention/priority/next actions, confirmation aging/follow-up, controlled changes/replacements, consistent expiry processing and concrete Data Health.
- one read-only customer AI Assistant with exactly nine allow-listed tools, shared quota/budget controls, an Admin-controlled multi-provider runtime/Behavior Studio, lazy embedded discovery, and an optional Admin-only deterministic-redacted transcript layer in a separate dedicated Redis store. Transcript logging defaults OFF and uses bounded TTL/deletion.

## Explicitly not implemented

Generic standalone Services, motorbike fleet operations/live integration, Bus, a real payment provider, QR/link, payment webhook, payment transaction/paid state, refund, payout, settlement and customer accounts do not exist. Trip Finder itself creates no request record, hold, Booking, profile or payment; only an explicit Phase 8 request creates a Booking. Phase 9 readiness/checkout drafts never collect money, Phase 10 only projects existing truth, and Phase 11 only operates those states. Phase 12 automates Supplier communication through one shared Telegram bot and private mapped groups while leaving database Confirmation/Operations authoritative. Application-only Phase 12H adds live bot/webhook diagnostics, Production-only repair and rotation guidance without changing migration 033 or Supplier/chat mappings. Phase 13D's AI remains read-only, fail-closed and disabled for customers until explicit owner activation; there is no AI mutation, raw transcript debugger, model-training pipeline or automatic provider failover. Transport remains clearly marked future. Combo is shown as usable only when at least one genuine published Package passes public eligibility; otherwise it remains `Sắp có`. Supplier/Partner status and private economics do not change verification, price confidence, availability, search ranking, Trip Finder ranking, checkout readiness or operational priority.
